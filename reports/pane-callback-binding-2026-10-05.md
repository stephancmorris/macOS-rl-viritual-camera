# Source-pane callback command binding — 5 October 2026

Child https://trello.com/c/LQLaXBUY under CHANNEL-CMD https://trello.com/c/f3cIWbfc, linked to CONSOLE https://trello.com/c/Ck2EP2Yg. Base `d720042` on `codex/alfie-quality-sprint-2026-10-04`.

The source pane's tap and hold handlers deferred show.makeCommand until callback invocation. A retained Preview B handler invoked after entering Edit Live A created a current-revision A command using B's coordinates. The coordinator guard could not reject an old revision because the callback minted a new one. A switch away and back, or a channel Stop/restart, likewise revived old callbacks.

The pane now captures its channel's command epoch and the show's control-target revision when returning a handler. The event constructs its action for that fixed channel, with the existing two-second host-clock expiry measured at event arrival, and passes the captured revision through show.dispatch. Handler creation refuses a pane that no longer owns the control target. Existing target, epoch, running-state and Edit Live admission still determine whether the effect can run. ShowCoordinator, Take, routing and framing policy are unchanged.

LivePaneCommandTests captures the actual tapHandler/holdHandler properties consumed by the view; it does not copy their dispatch expression. Nine definitions produce 25 runs. Cases cover old Preview→live and live→Preview callbacks, B→A→B without a channel epoch change, direct channel Stop/restart without a show-revision change, refusal to create handlers from a stale pane, and an old manual callback that must leave a newer shot move intact. Fresh Preview, explicit Edit Live and single-input A controls cover manual placement, Detect selection and locked-subject retargeting. Cross-target cases compare both channels' epochs, shot revisions, modes, manual points, ownership, pending gestures, locks, detection generations, zoom and crops; routing stays unchanged.
