MultiInputCheck previously recomputed evaluation context for each Program window, while ShowCoordinator stored the result under its completion-time fingerprint. A changed profile, format, mode, route or Program/Preview role could mix workloads and save the old sample as evidence for another setup. A reset Preview counter also used wrapping subtraction followed by trapping Int conversion.

A live check now mints an immutable binding with its starting fingerprint/context, Program/Preview roles, router generation, weak owner and exact channel instances, source generations and control epochs. Each live window validates that binding before ingestion; evaluation uses the starting context. The guarded save validates again and consumes the binding once, recording under the starting fingerprint. Cancellation/replacement retires old bindings. A refused save publishes cancellation, and console refresh invalidates a finished label when its measured setup changes. Historical matching, certified-record preservation, policy version, valid thresholds, Start trial behavior, Take/routing and two-input limits remain unchanged. Normal frame/shot/recovery revisions are not added to the binding.

Counter deltas require a nondecreasing UInt64 count and an exactly representable Int; invalid/reset counters cancel instead of trapping. Live subtraction also checks repeated <= rendered before calculating new frames. Synthetic dimensions/rate and closed-window DEBUG seams test the production binding/save path without devices or waiting for real sample windows.

Synchronous @Published notifications required a separate lifecycle truth and an explicit pending-publication drain. Binding/callback state is installed before the warm-up notification, and start/completion revalidate the same binding afterward. A newer check or cancellation from an observer therefore survives the old notification. Independent review also caught that Phase equality could loop forever for a result containing NaN; the final drain uses a pending flag, preserving evaluator policy. The actual nonfinite aggregate regression returns after exactly one finished event. These review issues were repaired before final verification.
