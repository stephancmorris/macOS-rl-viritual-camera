## Scope and interpretation

The rehearsal uses synthetic raw perception and actual evidence-adapter/readiness/policy paths. Preparation is an intent recorded before command commit; it is never relabelled completed preparation. The cut-policy event precedes the existing notice/permit path. The rehearsal performs an explicit manual Take without firing the automatic scheduler. All row provenance remains synthetic. No independent subject-quality/opportunity labels or model identity are inferred.

Study parameter versions cover the materialized effective style, readiness, adapter and judge-limit groups. A reused version with changed groups or a backward version drops capture with loss; the latest binding is bounded and reset for each renewed log. Legacy comparison capture shares the namespace but uses a policy-derived partial snapshot: run it in a separate renewed session. Simultaneous comparison/explicit capture is unsupported and can drop records. A segment/style transition also needs a new supplied version; the transition pair can be incomplete until capture is reconfigured. Stop can lose its terminal action record when running-source provenance disappears; this pre-existing production gap remains open. The synthetic rehearsal does not exercise those transitions or claim a complete study. Missing configuration remains unavailable. Explicit cut context identifies the provenance of supplied history/timeline/candidate data; unknown/mixed provenance refuses capture. An arbitrary judge is neither invoked twice nor assigned an inferred identity. Unmapped cut reasons remain `observation/unclassified`, so precise reason detail is unavailable in schema 1/2.

The lifecycle checks suspend synthetic executor operations at actual start/reconnect boundaries, preserving Stop/replacement ordering without camera permission, a capture device or receiving output. The existing 500 ms settling interval is unchanged. Recorder checks use isolated temporary files and controlled writers; no operator recording is read, changed or deleted. A partial append rolls back to the prior JSONL boundary. Failed rollback closes the writer, rejects later batches and surfaces an error; an unrecoverable file can retain an incomplete tail. Successful-batch totals do not prove damaged-file completeness or power-failure durability.

## Additional framing-loader integrity follow-up

The remaining allowance supported a verified consumer-side fix under PRIVACY: the loader previously admitted non-object rows, invalid FPS and NaN crop labels that could crash training or create NaN cloning actions. It now validates the shapes and finite numeric fields used by consumers, positive finite numeric FPS, provided session identity and completed row-count consistency. Totals bind to physical persisted rows, not maximum source index. Malformed JSON is refused with session/line/field context instead of disappearing. Validation also runs for sessions below `min_frames`, so malformed short sessions now raise rather than being ignored.

Twelve new temporary-corpus tests pass, as do four existing checkpoint-trust tests; the existing 100-row NumPy-generated fixture loads with consistent metadata. Independent review found no blocker in this bounded change. Optional legacy metadata/fields, fractional FPS and arbitrary subsampling/index strides remain compatible. Environment/BC timing calculations are unchanged: the audit reproduced compressed-time velocity across missing observations, and that timing contract remains a separate follow-up. Geometry ranges and float32 arithmetic safety are not established by finite-value validation. Gymnasium/Torch were unavailable, so no full pipeline run or model-quality claim is made. App build inputs are unchanged after the validated Swift/Release run; [validation.json](validation.json) separately hashes the loader.
