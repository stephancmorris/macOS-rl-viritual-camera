# [S2] Extract channels and prove two independent inputs

**Status:** implementation brief subordinate to [the R2 Program / Stage design](../ALFIE_MULTICAMERA_SPEC.md). The historical S2 dual-HDMI references in older notes are superseded. **Trello:** https://trello.com/c/4sFQx8lb and the R2 `CHANNEL`, `DEVICES`, `CHANNEL-CMD`, `SCHEDULER`, `ROUTER` cards. This file is a prompt for a bounded architecture sequence, not a claim that R1's full release gate is certified.

Implement only after `R1-GATE`, in reviewable steps. First move the single `ProgramOutputManager` into a minimal show-level facade without changing A's behavior. Then extract A's capture/detector/composer/crop/mode/preset/one-rung zoom/pan/identity/last-good state into a channel. The show coordinator owns the one Program Display or virtual-camera route, frozen `ShowStandard`, and diagnostics aggregation. Prove A-only equivalence, including output cadence, HOLD, restart, current command admission, and existing tests, before starting B. Then give each channel its own serial capture configuration executor, lifecycle/source generation, one-slot capture mailbox, observation generation, command epoch and discrete shot revision. Instantiate B with its own session/detector/identity/composer/crop/motion state and a distinct claimed device. A failed or unplugged B leaves A running and routed.

Move `CropEngine`'s hidden static render queue behind a bounded fair scheduler; keep one render in flight per channel and no growing frame backlog. An immutable packet records channel ID, source generation, capture sequence/time, shot revision, legal crop, render time and buffer lifetime. Reject retired async completions. Commands bind to a stable A/B target at creation; session commands remain show-level. Do not let a later Preview selection retarget a queued command. Separate per-channel command epochs, source generations and UI selection revision.

Keep one output router and one output clock. The existing XPC extension remains one stream. Program starts as A only after A has a legal fresh rendered frame and the selected output sink is ready; B discovery/start cannot become live automatically. The router rejects old or out-of-order frame packets and maintains monotonic downstream timestamps. Hot unplug or reconnect never swaps cameras. Render/source fault policy, explicit destination behavior, and buffer retirement follow the canonical spec.

S2's proof UI may be minimal, but its Program pane must show the actual routed feed and its channel label. A B control/preview click must never cut A. Any proof Take uses the canonical fresh legal render gate; it is not a way to bypass admission. S3 owns the final console and broad qualification. No second HDMI output, second CMIO device, Channel C, direct SDI, speech, physical hardware, or T5a easing changes.

Acceptance: deterministic isolation and generation tests; two real capture devices started together; A tracking while B pans/zooms; bounded scheduler fairness; A survives B start failure/unplug; exactly one routed output; no accidental Take or raw-source fallback. Record device/format/rate and output evidence. Defer claims of sustained two-input certification to `ADMISSION` and `MULTI-QA`.
