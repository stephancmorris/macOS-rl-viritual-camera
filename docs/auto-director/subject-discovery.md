# B-10 bounded subject discovery — software candidate

This is a disabled-by-default software slice, with synthetic verification. It does not approve a discovery rate or qualify a rig. The [D-03 workload protocol](../../reports/auto-director/workload-plan.md), [named-rig budget](../../reports/auto-director/discovery-rig-budget.md), C1/C2 decisions, permitted exposure and live evaluation remain pending. No new recording or study collection is authorized here.

`CameraManager.configureSubjectDiscoveryForStudy(_:eligibility:)` is available only in Debug. The normal app installs no configuration. A missing or invalid configuration disables discovery; Release refuses the detector's discovery mode. Every study configuration explicitly supplies its revision, maximum starts per second, maximum result age, maximum stable centroid speed, A-14 selector parameters and optional calibrated position-hint zone. The code supplies no numeric production defaults or inferred stage geometry.

The controller supplies a fresh context containing current Program, route generation, authority epoch, policy and nomination revisions, scan permission and a separate acquisition permission. Scan permission never grants acquisition authority. Existing Director qualification and nomination prerequisites remain in force: an unlocked input cannot manufacture a nomination to bootstrap its own authority. An explicitly admitted scan-only study can expose candidates without acquiring one; an unauthorized real controller must refuse acquisition.

The channel independently requires a running, present, unlocked, inactive Wide input that is off air, has no operator gesture and has the show's perception scheduler. Its source generation, control epoch and shot revision join the show context and configuration revision in the work binding. The binding is checked before requesting work, after obtaining a perception permit and after detector completion, immediately before any acquisition effect. Source/session, command, nomination, configuration, policy and role changes retire work. Every Take origin retires discovery synchronously before the Take's observers/checks/effect; a refused operator Take also retires its prior work without changing the recorded N1 behavior.

Discovery uses a distinct full-frame rect-plus-pose detector plan. It excludes the face request. A selected local candidate enters the existing acquiring state with its body ROI; subsequent ordinary acquisition runs the face-gallery path and establishes identity readiness. A discovery candidate is neither prepare-ready nor cut-ready. The generic Director command allow-list still permits only shot-size actions. Operator nomination/retargeting uses the existing ROI command path and supersedes automatic provenance. A successful automatic acquisition retains its explicit origin while that same source and lock remain current.

One shared channel detection-in-flight flag bounds retained discovery input to one frame. Discovery obtains the existing shared perception permit, so it introduces no additional executor lane or frame queue. Both requests and actual executor starts obey the explicit rate without saved credits. A delayed permit cannot produce a catch-up burst. Local stability uses measured centroid speed between fresh observations; moving people and stale observation gaps reset it. Several plausible subjects remain ambiguous through A-14; no close-up is guessed.

A thread-safe token serializes retirement against the start of Vision on the detector's serial executor, after permit/dispatch/downscale waits and immediately before inference. A retired pending call skips inference. Retiring a waiting discovery request cancels only its perception waiter; render and ordinary tracking are unaffected. Once Vision has started it is non-preemptible: retirement counts a running overlap and rejects its result before detector tracking publication and acquisition. The app does not wait for Vision or delay manual Take. This cannot establish the literal B-10 gate that no full-frame work ever overlaps a new Program role; D-03 explicitly leaves that interpretation and measurement as an owner/integration question.

Discovery observations never enter `DetectionFrameStore` or composer consumption before acquisition. Plain numeric/categorical metadata includes request/start/completion counts, pending cancellations, retired running calls, rejected results, acquisitions and latest permit/service times. Counters are sampled after completion; no frames, names, face signatures, persistent study files or new per-frame `@Published` properties are added. `subjectDiscoverySnapshot(at:)` expires candidate/pick status by actual captured-frame age and the strictest supplied age limit, including when no more source frames arrive. The existing UI refresh samples it.

Synthetic tests cover missing/invalid budgets, off-air admission, cadence after stalled permits, cancellation versus running overlap, stale source/authority bindings, malformed or expired results, stability and ambiguity, scan-only permission, normal acquisition/gallery readiness, nomination supersession, gesture/source-loss/stop refusal and the actual detector executor's retirement gate with synthetic work. These demonstrate software behavior only. Named-rig workload limits, measured `[SOAK]` exposure, real output behavior, utility and qualification signatures still require their existing owner gates.
