# Director shadow storage

B-04 candidate · 18 October 2026. Metadata infrastructure and synthetic tests only; no live study or qualification. This engine stack follows [the schema](shadow-record-schema.md) and recorded C3/AI-4 decisions in [the register](../handoff/stage3-4/DECISIONS.md).

`DirectorShadowLog` is separate from `DiagnosticsLog.swift`, which also compiles into the camera extension. Its app-only factory places `director_shadow_<session UUID>.jsonl` files beside the existing diagnostics files. It never serializes a camera, pixel buffer, point, filename, source URL, person UUID, face gallery, transcript or raw error string. The A-09 schema validates each record before encoding and again when decoding an export.

## Configure explicitly

The owner supplies positive `maximumRecordBytes`, `maximumQueuedBytes`, `maximumFileBytes` and `maximumStoreBytes`. A record must fit the queue and session file, and a session file must fit the total Director store. No queue/storage budget is silently chosen by the app. Tests supply synthetic limits; they are not production recommendations.

Create `DirectorShadowLog.besideDiagnostics(limits:)`, then pass it to `ShowCoordinator(directorShadowLog:)`. The optional argument defaults to nil, so an unconfigured show performs no new disk logging. The storage/export API and event hooks accept only explicitly configured limits. The optional export provider is nil when no log is configured; opening Settings or its export UI never creates a writer, chooses storage budgets or enables a Director level. The export gallery supplies synthetic metadata and explicit fixture limits separately. No qualification or operating level is restored from a log.

One producer submits typed records in sequence order. `append(_:provenance:)` returns queue admission, not a successful filesystem write. Callers may inspect `metrics`, or await `flush()` for a FIFO barrier. Flush is not a power-failure durability guarantee. Encoding is bounded metadata work at a Director tick or operator event; all filesystem reads, writes, pruning and export occur on a shared serial utility queue. There is no frame-path I/O or per-frame published state.

## What is actually recorded

The configured controller emits typed operator camera attempts/results, level/handback/takeover actions, and correlated Take attempts/results. A completed Take is logged only after the router committed the new Program; refusal is distinct. A synchronous camera command returning accepted stays `accepted`, never a fabricated completed downstream picture. Safety-origin commands and an automatic preparation-failure pause are not labelled human actions. Explicit console and Session-menu Show Stop now use a separate operator origin. Their source-bound attempt/result observes the synchronous logical stop of all attached channels and reset to Program A; `accepted` does not mean an asynchronous capture executor or receiver has finished stopping. Lifecycle callers remain unattributed. Missing, mixed or starting source provenance and changed source objects, membership, revisions, roles, route or session refuse a terminal record. A later or duplicate result cannot borrow an earlier origin.

Without an explicitly configured cut study, the ordinary tick emits `cutPolicyUnavailable`; it does not invent a cut decision. An explicit preparation capture records `wouldPrepare` after successful enqueue and before dispatch. An explicit cut capture records the actual `CutPolicy` result before notice/permit effects, using that evaluation's clock, raw evidence, evaluated readiness and supplied timeline. These are decision intents, including when later effect validation refuses. They do not establish completed preparation, an automatic Take, subject correctness or qualification.

Capture is optional and requires an explicit parameter version and homogeneous provenance for all contributing data; cut context separately identifies its supplied timeline/history/candidate provenance. The materialized snapshot contains the effective style, readiness and adapter parameters plus cut judge limits. Reusing a version with different groups or submitting an older version is dropped with loss accounting; a renewed log resets this bounded latest-version binding. Comparison and actual-decision records share that namespace. `configureCaptureForStudy` optionally installs a provider that receives the actual policy/preference revision and materialized style/readiness/adapter/judge-limit groups, then supplies only their version and contributing provenance. The provider cannot replace execution settings. It is resolved for pre/post segment actions and comparison/decision records; a declined binding drops capture without falling back to legacy/static identity. Reentrant changes to the key, sources, roles or capture configuration refuse the earlier binding. A style change needs a greater supplied version; an identical complete group can reuse its version. No version is automatically allocated from policy revision. Without this provider, legacy comparison still records policy-derived partial groups and requires a separate session from conflicting explicit capture. `policyRevision` is not silently used as a parameter version. Existing segment-only comparison capture remains supported. Missing binding leaves parameters unavailable; mismatched provenance or rebound version refuses capture without changing effects. Ordinary control records can use the current explicitly configured cut-study parameters and actual current Program shot; they do not retain a previous timeline. Test-only readiness authorization overrides are not exported as measured readiness.

The current wire vocabulary cannot express every `CutPolicy` reason. Such decisions retain `observation/unclassified` rather than guessing a more specific reason. A configured arbitrary judge is not re-invoked or assigned an inferred model identity for logging; missing judgement attribution remains missing. Unknown timeline/history fields remain omitted. Known preferences alone identify their schema version, not a complete parameter snapshot.

Source provenance comes from every actual running, non-starting input's active source and source identity. A validation clip remains recorded evidence; it is never classified from the output route or shadow mode. Unknown or mixed provenance is omitted and counted as lost under schema 1. Debug-only tests may inject synthetic provenance. Aliases are session-local `input-N`; source device names and IDs are not logged. A new show renews the session UUID and sequence rather than merging clock domains. Segment aliases are derived by HMAC-SHA256 over the internal segment UUID with a private random per-session key, truncated to an opaque 128-bit token. Only that token is serialized. The key is renewed after successful log renewal and is never stored or exported. This keeps aliases stable within a session without retaining a growing map of every segment ever seen. It is a source-level memory bound, not a memory-zeroization or anonymity claim.

## Capacity and loss

Queue reservations bound pending records before encoding. Oversized/invalid records, mixed provenance, stale sequences, duplicate record IDs and failed writes are dropped. Producer losses and prior queued-write failures are carried separately so a later missing sequence is never attributed to an earlier queued record. The next successful record reports the additional loss in `droppedRecordsBefore`; metrics also report total drops, write successes, pruning and storage errors.

A full session file stops accepting further writes rather than growing or silently rewriting old lines. To keep the total Director store bounded, the writer may evict the oldest other managed sessions. Quota eviction can therefore remove unexpired logs: thirty days is a maximum retention policy, not a minimum preservation promise. Only strict UUID-named Director JSONL files are managed. Unrelated diagnostics, user notes, directories and symlinks are not followed or deleted.

Do not infer complete capture from a successfully exported file. Preserve planned run/session references, sequence gaps, drop metrics and evidence exclusions in the [qualification assessment](../../reports/auto-director/qualification-protocol.md). Missing sessions or intervals remain unverified; deleting a log cannot create a passing denominator.

## Expiry and explicit export

C3's recorded thirty-day metadata retention uses the original `recordedAtUTC`, not file modification time or export time. Writes require nondecreasing UTC and sequence within a session; future/expired timestamps are refused. Managed-file expiry is based on its first original record; corrupt or future managed headers are removed conservatively. No raw invalid token is converted into a plausible timestamp.

Pruning runs at initialization, append, explicit maintenance, inventory and export. A UTC reference is captured once per operation. Schema UTC is floored to millisecond precision so formatting the current clock cannot round a valid sample into the future; already representable wire milliseconds round-trip unchanged. Detected wall-clock rollback discards managed ordinary logs and refuses that operation. The in-process clock history follows renewed sessions. After process restart, future record timestamps still fail closed; no trusted clock service or persistent clock ledger is claimed. When the app is closed or idle, physical cleanup waits for the next such operation; this is not an installed background deletion service. Expired data is never eligible for export. The writer manages only its Director namespace, not every existing diagnostics/training file or external copy. E3 media retention is a separate open decision.

`retainedSessions()` waits behind queued writes, prunes expired/invalid-header files, then validates the bounded retained sessions. It returns only opaque session UUIDs, original UTC bounds, record counts and evidence classes. It reports excluded and pruned **file** counts; it cannot invent a count of records in an unreadable or already removed file. Unrelated files, symlinks and nonregular entries are never imported as sessions. Inventory is advisory: a selected source is validated again during export.

The operator explicitly selects session UUIDs, an inclusive **From UTC / Through UTC** interval, and a local destination. Pass that choice as `DirectorShadowExportSelection` to `export(selection:toNewBundle:)`. The destination must be a new directory outside the managed log directory and its descendants, including resolved symlink aliases. Existing files/directories and dangling symlinks are refused. Selection and date validation occur before publication; a missing or corrupt selected session refuses the entire operation rather than exporting a plausible subset. Valid records outside the selected interval are counted separately. Original source files, UTC values, evidence classes, IDs, sequence gaps and reported loss remain unchanged.

A successful bundle contains exactly `records.jsonl` and `manifest.json`. The manifest is generated from the actual exported rows and has the eight [schema-1 contract fields](shadow-record-schema.md#8-privacy-retention-and-explicit-export): `exportSchemaVersion`, `exportID`, `exportedAtUTC`, `sessionIDs`, `recordCount`, `evidenceClasses`, `recordSchemaVersions` and `retention: "explicitExport"`. Session IDs, classes and record-schema versions are sorted unique sets. There are no paths, names, media, qualifications or arbitrary extension fields. The Swift manifest is writer-only; the [offline report reader](shadow-report.md) strictly validates external bundles, including duplicate keys and count/set mismatches. Manifest consistency is not proof of complete capture, dataset authenticity or live qualification.

Both members are first written to a private adjacent staging directory. An exclusive atomic rename publishes the new directory only after both writes succeed. Failures clean up staging and never overwrite an existing destination. Source reads use the configured record/file/store limits and refuse final symlinks; duplicate JSON keys, non-integer wire spellings of integer fields (such as `schemaVersion: 1.0` or `1e0`), unknown fields, invalid record IDs/order and invalid original UTC cannot leak ignored raw payload into export. All filesystem work remains on the utility queue. This is a publication guarantee, not a power-failure durability claim.

`export(session:to:)` and the controller's older `exportShadowLog(to:)` remain **legacy unbundled JSONL APIs**; the operator-facing chooser uses the bundle API. No upload or implicit export occurs. `finish()` prevents new writes while retained data can still be exported within policy. Explicit exported copies remain under operator control after the original's retention deadline; neither export nor analysis renews the ordinary source log. Partial UTC selections still expose sequence offsets and missing action pairs; they do not manufacture a complete study interval.

## Validation boundary

Synthetic tests exercise typed round-trip/export, retained multi-session inventory, inclusive UTC boundaries, the eight-key shared manifest fixture, nonoverwrite/staging cleanup, corrupt/duplicate-key files, strict size/queue/store bounds, sequence-correct loss accounting, cross-session duplicate record IDs, exact thirty-day expiry, refreshed file modification times, clock rollback, all millisecond roundtrips, source-descendant/alias refusal, symlink/unrelated-file protection, session renewal and actual controller Take correlation. App and camera-extension builds verify isolation of the app-only writer. No camera, person, microphone, live route, consent or sign-off is exercised by these tests. Runtime workload and approved storage budgets still require the named-rig study.

## Capture continuity follow-up — 22 October 2026

A dispatched operator `stopSession` attempt can retain one in-memory source-bound snapshot only after queue admission. Its matching immediate result must preserve the same source objects/identities, roles and routing, with the exact accepted Stop revision transition or unchanged refused world. Restart, intervening rows/attempts, detachment, duplicates and rebinding invalidate it. No source/device identity is serialized. The result's evidence class describes the attempted source origin; the camera stays stopped. The existing context.running field describes show authority, not per-camera running state. Direct ShowCoordinator.stopShow/termination remains uninstrumented by this command path.

CutPolicy evaluates its judge once through an optional-attribution protocol method, then passes the exact returned judgement, filtered context and already evaluated gate to capture after the decision exists. Arbitrary existing judges retain one call and unavailable identity. Rule/recorded judges identify themselves explicitly; learned evaluation identifies its actual learned result or rules fallback. The recorder includes one attributed judgement and event index when available; missing/malformed model identity stays omitted. Logging never re-invokes the judge or infers model identity. The wire reason vocabulary and independent-opportunity limitations remain unchanged.

The offline matcher accepts caller-supplied complete-group segment versions independently of policy revision, retains strict action/source/model/route/token checks, and rejects conflicting full groups under one version across segment types/evidence classes. Full snapshots below the session version high-water mark block scoring; unavailable rows never reset it. Legacy partial v1/v2 input keeps its historical contract. See the [candidate report](../../reports/capture-continuity-2026-10-22/README.md) for exact evidence and remaining gates.
